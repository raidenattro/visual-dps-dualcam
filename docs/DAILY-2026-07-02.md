## 一、代码提交（已入库）

### 1. headless `pose_frame_interval` 双重 sleep 修复（`96c10cf`）

- **现象**：`pose_frame_interval≥2` 时 pose 墙钟间隔约为配置的 **(2N−1)/N** 倍偏慢（interval=2 实测 ~200 ms，应为 133 ms）。
- **根因**：headless RTSP infer 主循环中 **skip tick 睡 `frame_period`** 与 **pose tick 睡 `interval×frame_period`** 叠加（双重 pacing）。
- **修复**（`services/inference_service.py`）：pose tick 末尾 **仅睡 1×`frame_period`**，降频由 skip tick 承担。
- **挂载**（`services/inference_container_service.py`）：bind mount 列表 **补齐 `services/inference_service.py`**，改代码后 **restart UI** 再停启 infer 即生效。

### 2. 碰撞日志墙钟毫秒（`51e7f0e`）

- **`services/wall_clock.py`**：`wall_time_str()` 输出 **`YYYY-MM-DD HH:MM:SS.mmm`**。
- **`services/event_engine/worker.py`**：`[COLLISION][HIT]` / `[ALARM]` 的 `time=` 沿用上述格式，便于用 **Δtime** 核对 pose 间隔。

### 3. 监控页「画面」开关（`f352eaa`）

- **`web/src/pages/MonitorPage.jsx`**：`showVideoLayer` 默认 **关**；切换 `cameraId` 时重置为关。
- **`web/src/components/MonitorPreviewStage.jsx`**：关画面仅停 WebRTC/HLS/MJPEG；骨架/ROI 独立开关；无画面时用 `liveInferWidth/Height` 或 `annotationSize` 布局 overlay。
- SSE 在 infer 运行时照常订阅；标注模式仍强制开画面。

### 4. ALARM infer 重启后失效（方案 A，`525d784`）

- **现象**：infer 重启后 worker 有 HIT 无 ALARM（`_box_last_alarm_frame` 保留旧 `frame_idx`，冷却判定长期失败）。
- **修复**：
  - **`services/event_engine/collision.py`**：`reset_infer_session()` 清空 `_box_consecutive_hits`、`_box_last_alarm_frame`、`person_assigner`。
  - **`services/event_engine/worker.py`**：每路 camera 记 `last_frame_idx`；若 `frame_idx < last_frame_idx` 视为 infer 重启并 reset，打 info 日志。
- **未采用方案 B**（infer 传 `run_id`）：主场景（worker 在线、infer restart、`frame_idx` 从 1 重计）已覆盖；后续若需断链期间 infer 重启可再补。

### 4.1 `pose_frame_interval` 双重 pacing（修复前后）

**修复前**（headless，推理较快、sleep 睡满时）：

\[
T_{\text{实际}} = (N-1)\times\frac{1}{15} + N\times\frac{1}{15} = \frac{2N-1}{15}\ \text{s}
\]

| N | 配置目标 | 修复前实测 | 修复后实测（本分支） |
|---|----------|------------|----------------------|
| 2 | 133 ms | ~200 ms | **~130 ms** ✓ |
| 3 | 200 ms | ~334 ms | （`test/timeoffset` 验证 **204 ms**） |

**相关代码**（`services/inference_service.py`）：

```python
# skip tick（不跑 pose）
sleep_skip = frame_period_sec - elapsed_skip          # ≈ 67 ms

# 修复后 pose tick 末尾：仅睡 1 tick（勿再乘 pose_frame_interval）
sleep_sec = frame_period_sec - elapsed_loop
```

**配置链路**：`runtime_config.json` → `inference_container_service` 注入 `INFERENCE_FRAME_RATE` / `INFERENCE_POSE_FRAME_INTERVAL` → infer 容器环境变量。

### 4.2 修复后验收日志（`test_camera`，2026-07-02 15:24）

`pose_frame_interval=2`，`alarm_min_consecutive_frames=3`，`COLLISION_LOG=1`：

```text
[COLLISION][HIT]  time=2026-07-02 15:24:02.578 ... frame=376 ...
[COLLISION][HIT]  time=2026-07-02 15:24:02.705 ... frame=377 ...   # Δtime 127 ms
[COLLISION][HIT]  time=2026-07-02 15:24:02.839 ... frame=378 ...   # Δtime 134 ms
[COLLISION][ALARM] time=2026-07-02 15:24:02.839 ... frame=378 ...  # 第 3 帧 HIT 同拍
```

- **墙钟 Δtime**：127 ms / 134 ms，均值 ~131 ms，对齐 **133 ms**（7.5 fps）。
- **`video_sec` 步长**：25.000 → 25.067 → 25.133，每帧 **67 ms**（15 fps 索引，与 interval 无关）。
- **ALARM**：连续 3 帧 HIT 后在 frame 378 触发，参数生效。

### 4.3 infer 重启后 ALARM 恢复（方案 A 验收要点）

1. 联调至出现 `[COLLISION][ALARM]`，记下 `frame`（如 378）。
2. **restart infer 容器**（或 UI 停启 infer）。
3. 再次触发碰撞：event-worker 日志应出现  
   `infer frame_idx regression camera=... frame=1 last=378; reset collision session`（`last` 为重启前末帧）。
4. 连续 3 帧 HIT 后应恢复 `[COLLISION][ALARM]`。
