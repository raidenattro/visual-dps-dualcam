## 一、背景与目标

- **现象**：立体配对成功时仍有个别 **3D 骨形扭曲**；**腕部抖动**相对旧版逐关节抬升更明显；历史存在 **贴墙 token 用 clamp 前腕、3D 用 clamp 后** 的不一致；五官 3D 偶发 **贴地/乱线**。
- **本日目标**：
  1. 尝试 **方案 A 整体抬升**（躯干锚 + 四肢 depth_ref）改善结构，且不恢复整窗平滑（吞吐约束）。
  2. **统一 worker 与前端**：贴墙与 `persons_3d` 同一几何；3D 不画五官。
  3. 方案 A 现场不满意则 **回滚**，保留对齐与五官策略。
  4. 清理 **未使用的直播平滑代码**；输出 **域内 RTMPose 微调** 交接文档（视频数据充足，转其他仓库训练）。

硬约束未破：不改 `visual-dps` / `visual-dps-pick-state`；碰撞仍是 3D `contact_slots`；产物写本仓 `localdata/`。

## 二、方案 A 结构化抬升（已上线后回滚）

### 实现（commit `0cd7b6c` · `6433f82`）

| 内容 | 说明 |
|------|------|
| `dualcam/lift.py` · `lift_person17` | 先抬肩髋 5/6/11/12，再 limb；禁 limb `ray_plane`；大 gap 仍倾向双路加权 |
| `dualcam_processor` | 接入 `lift_person17`；**贴墙 `contact_slots` 改为 clamp 后 `xyz`**（与 SSE 3D 一致） |

### 现场结论

- **扭曲**：部分场景略好。
- **腕抖**：相对 **逐关节 `lift_point` + prev 深度** 更差（四肢 fallback 强绑 **肩锚 depth**，肩本身每帧 stereo 也在动）。
- **后续试错**：曾将 **腕单独改回 `lift_point`**，整体仍不满意 → **整方案回滚**（见 §五）。

## 七、分析与文档（对话结论摘要，未单独 commit）

- **`det_size` / JSON `rtmpose_onnx_*_size`**：推理尺寸由 **`model_registry` + `models.backend/det`** 决定，JSON size 项不生效。
- **720p + det-m**：letterbox 640 为整图缩放，非裁剪窗；与腕抖无直接因果。
- **后续约束方向**（未实现）：单帧 IK、重投影门控、禁 limb mono、腕深度轻量 EMA 等；优先 **域内训练** 治 2D 根因。
