## 五、lag 监控 + 跨夜观测

### 脚本

`scripts/monitor-pose-lag.sh` — 每 **300s** 一行，日志 `logs/pose-lag-YYYYMMDD.log`：

```bash
cd /home/hycx/zyrao/visual-dps-dualcam
tmux new -s lag
./scripts/monitor-pose-lag.sh          # 一直跑
./scripts/monitor-pose-lag.sh 300 24h  # 限时
```

输出按 **worker A/B 汇总 + 各 shard 明细**：`consume`（消费 msg/s）、`ingress`（入流）、`d_lag`、`pending`、`xlen`、worker CPU、`infer` 容器数。  
`xlen≈2000` 是 Stream `MAXLEN`，不是积压；看 **lag / pending**。

### 观测窗口（`logs/pose-lag-20260904.log`）

| 项 | 值 |
|----|-----|
| 启动 | 2026-09-04 **17:38:30** |
| 日志末拍 | 2026-09-07 **09:27:28**（约 **62h**，**747 拍**） |
| infer | 启动 **16** 路 → 17:48 起稳定 **20** 路，全程在线 |
| WARN / CRITICAL | **0**（阈值 lag≥50 / ≥500） |

### Worker 汇总（746 个有效 tick，baseline 除外）

| | A（shard 0–7） | B（shard 8–15） |
|---|---|---|
| consume | **27.7 msg/s** | **41.6 msg/s** |
| CPU | 均值 **15.7%**（6–32%） | 均值 **23.4%**（10–48%） |
| lag | 均值 **0.21**，max **3** | 均值 **0.51**，max **4** |
| pending | 多为 0，峰值 **6** | 多为 0–3 |

`consume ≈ ingress` 全程成立（1492 个 worker 汇总 tick 偏差 >0.05 的 **0 次**），**入多少吃多少，无 Redis 积压**。  
与 0902 overnight（6 巷道 / 12 infer：A **47**、B **24** msg/s）相比：总吞吐相近（~70 msg/s），但 **CRC32 分片倒转**——现网 **B 更重**（新巷道更多落在 shard 8–15）；CPU 明显更低，余量充足。

### 活跃 shard（9 条巷道有流量）

| shard | worker | 平均 consume | 备注 |
|-------|--------|-------------|------|
| 1, 2, 4, 7 | A | ~**6.9 msg/s** | |
| 10, 11, 13, 14 | B | ~**7.0 msg/s** | |
| **12** | B | ~**13.9 msg/s** | 约为其他的 2 倍，可能同 shard 两路/两巷道 |

### 按日 lag

| 日期 | lag>0 占比 | 平均 lag |
|------|-----------|---------|
| 09-04（半日，17:38 起） | 24% | 0.32 |
| 09-05 | 28% | 0.39 |
| 09-06 | 27% | 0.37 |
| 09-07（至 09:27） | 20% | 0.27 |

偶发 lag 1–4、`d_lag` 尖峰最大 4：infer 帧率抖动或批量读 Redis 的瞬时差异，**下一周期即拉回**，非系统性跟不上。

### 结论

1. **20 路 infer / 9 巷道连续 ~2.6 天无积压**，双 worker 消费正常，`9d1c02e` 优化在扩路后仍成立。
2. **lag 不是现场「3D 延迟」主因**；若仍有观感延迟，优先查 infer 推帧或前端 overlay 路径。
3. `pending` 偶发 1–6 为 PEL 残留，lag=0 时可忽略；worker 重启后注意清僵尸 consumer。
4. 分片仍不均；加巷道时新 `aisle_id` 易继续砸在 8–15（当前 B 侧）。
