## 一、背景与目标

现场需要可观测 **RTSP 采帧 → 推理 publish pose → Event Worker 消费 → event 发布 / Java 回调** 各节点行为，便于排查延迟与丢帧；原有机制以 `print` / 可选 `COLLISION_LOG` 为主，**无统一 correlation（run_id / frame_idx）**，也缺少可持久化的流水线日志文件。

---

## 二、设计与调研（上午）

| 节点 | 原状 | 缺口 |
|------|------|------|
| 推理采帧 | `rtsp_capture` 重连 print | 无采帧时刻、无 per-frame 日志 |
| 推理 pose 完成 | 可选 `DEBUG-INFO` | 无 det/pose 耗时、无 publish 成功日志 |
| Worker 收 pose | 仅连接/reset 类 logger | 无 consume / 处理耗时 |
| Worker 发 event / 回调 | `[CALLBACK]*` + SQLite | event publish 本身无日志 |

结论：新增 **`pipeline_log`** 层（stdout + 可选文件），与 `COLLISION_LOG`（业务决策）分工；后续可合入 `pipeline_latency` 全链路 JSONL（`test/timeoffset` 分支已有实现，本日未合入）。

## 三、代码实现（WIP 提交）

### 1. 核心模块 `services/pipeline_log.py`

- 标准库 **`logging`** 统一管理（替代各节点 `print`）
- 阶段 tag：`rtsp_frame` / `infer_pose_done` / `pose_published` / `worker_received` / `worker_done` / `event_published` / `callback_enqueued`
- 采样：`pipeline_log.sample`（默认每 30 帧）；告警 `callback_enqueued` 不采样
- 输出：`stdout`（默认）+ 可选文件 `localdata/logs/pipeline/{role}.log`

### 2. 埋点接入

| 文件 | 变更 |
|------|------|
| `services/inference_service.py` | 采帧、`infer_pose_done`、传递 `run_id` |
| `services/pose_bus.py` | `pose_published`；PoseFrame 增 `run_id` |
| `services/event_engine/worker.py` | `worker_received` / `worker_done` / `event_published` / `callback_enqueued` |
| `inference_worker.py` / `event_worker.py` | 启动时 `apply_pipeline_log_config` + `configure_pipeline_logger` |

### 3. 配置体系（由 env 改为 config）

**`app_config.json`** 新增：

```json
"pipeline_log": {
    "enabled": false,
    "file_enabled": false,
    "dir": "localdata/logs/pipeline",
    "sample": 30,
    "stdout": true
}
```

- `runtime_config_service.py`：`get_pipeline_log_section()` + `pipeline_log.*` 公开项
- 优先级：**`runtime_config.json` > `app_config.json`**；环境变量 `PIPELINE_LOG*` 仍可临时覆盖
- 推理容器通过挂载的 `app_config` + `localdata` 读取，无需 compose 注入 env

### 4. 前端设置页

- `web/src/lib/cameraSettings.js`：`GLOBAL_PIPELINE_LOG_FIELDS`
- `web/src/pages/SettingsPage.jsx`：「流水线日志」区块（开关 / 写文件 / 采样间隔）
- 保存后需 **重启 event-worker 与推理容器** 生效

### 5. 其他

- `inference_container_service.py`：开发 bind mount 补 `pipeline_log.py`、`pose_bus.py`
- 单测：`tests/test_pipeline_log.py`（4 passed）

## 四、配置说明（现场启用）

**方式 A — 设置页**：全局设置 → 流水线日志 → 开启「流水线阶段日志」+「写入日志文件」→ 保存 → 重启 worker / infer。

**方式 B — 直接改 `app_config.json`**：将 `pipeline_log.enabled` / `file_enabled` 设为 `true`。

**日志路径**：

| 进程 | 文件 |
|------|------|
| Event Worker | `localdata/logs/pipeline/worker.log` |
| 推理容器 camX | `localdata/logs/pipeline/infer_camX.log` |
