## 三、压测结果摘要

### 1. 16 路 · worker-2 **可较为正常工作** ✓（0818 复现基线）

| 指标 | 5 min 观测（0818 14:46–14:51） |
|------|--------------------------------|
| 判定 | **稳定 ✓** |
| Redis lag | 均值 **2.54**，峰值 **10**，末样本 **0** |
| pose 消费速率 | **64.2 msg/s** |
| worker-2 CPU | 均值 **194%**（23–311% 波动） |
| 16× infer CPU | 均值 **1008%** |
| GPU | 利用率 avg **90%**，显存 **~16.2 GiB** |
| 端到端延迟（估） | 典型 **~193 ms**（lag 尖峰 10 时 ~310 ms） |

**解读**：单 worker-2 + `XREADGROUP count=1` 在 **16 路、~64 msg/s** 平台下 **lag 可维持 0–10 振荡**，event 与 infer **基本同步**，overlay/告警时序可接受。这是当前栈的 **sweet spot**。

报告：[`docs/test/stability-5min-20260818-1450.md`](./test/stability-5min-20260818-1450.md)

### 4. 路数对照表

| 路数 | lag avg | 消费 msg/s | worker-2 CPU avg | 稳定性 |
|------|---------|------------|------------------|--------|
| **16** | **2.5** | **64** | **~194%** | **稳定 ✓** |
| 22 | 1969 | 74.5 | ~239% | 不稳定 ✗ |
| 24 | 1999 | 76.4 | ~225% | 不稳定 ✗ |

**关键发现**：

1. **16 路下 worker-2 能较为正常工作**：lag 低、消费跟得上 infer，可作为生产/对照基线。
2. **22 路起 lag 顶满 ~2000**：infer 仍多产 pose，但 worker **消费平台 ~74–76 msg/s**，与 16 路相比几乎不增长 → 瓶颈在 **单 consumer 吞吐**，非单纯 infer 算力。
3. **24 路 infer CPU 升高，worker CPU 未线性暴涨**：本机 worker ~225% vs 现场 ~1377%，差距更可能来自 **14900K/32 线程 vs 9900KF/16 线程**、**现场标注更重**、**ONNX 默认线程数** 等，而非 `.env` 未对齐。
4. **临界点**：预计在 **17–20 路** 附近 lag 从 ≈0 转为持续爬升（22 路已明确过载）。

## 四、Redis 指标联调（本日）

| 指标 | 含义 | 本日观察 |
|------|------|----------|
| **lag** | 尚未投递给 consumer 的条数 | 16 路 ≈0–10；22/24 路 ≈2000 |
| **pending** | 已 `XREADGROUP`、未 `XACK` | 通常 1–2；曾见 1 条 **~2 h** 陈旧 pending（处理异常未 ack）+ 1 条在途 |
| **XLEN** | stream 长度 | 过载时常顶 **maxlen=2000** |

`pending=2` **不等于 2 个 worker**，而是同一 consumer PEL 里 2 条未确认消息。
