## 三、解剖先验（今天的主要工作）

反投影残差对某些自由度**完全不敏感**——翻过去残差一样，求解器就会随机乱选，画面上看着像骨折。逐个量化后加软先验：

| 先验 | 现象 | 权重 |
|------|------|------|
| `armBack` | 手臂甩到身后（肩后伸） | 8 |
| `headFwd` | 眼睛跑到耳朵后面，头和胸口箭头打架 | 40 |
| `noseFwd` | 鼻子落到两肩连线后方 | 40 |
| `elbowFwd` | 肘朝身前鼓出 = 反折（模型里肘是球窝的） | 8 |

实测（三段录像，逐帧连续推进）：

| 指标 | 改前 | 改后 |
|------|------|------|
| 眼在耳后 | 35.0% / 16.8% / 6.2% | 0.0% / 0.3% / 1.8% |
| 肘反折 >2cm（弯臂、手不过肩） | 19.2% / 31.4% / 12.6% | 8.5% / 1.4% / 2.9% |
| 肘反折 >5cm | 16.6% / 29.8% / 7.4% | 2.2% / 0.2% / 0.3% |
| 鼻在肩线后 | 1.4% / 2.8% / 3.6% | 全部 0.0% |
| 平均反投影残差 | ≈2.55 / 2.99 / 5.46 px | 2.71 / 2.97 / 5.59 px |

伸手够货那批帧（肩腕距 >0.5m，拣货判定真正依赖的姿态）反折 1.6/1.7/4.3% → 0.7/0.4/2.4%，平均值不变，未被带歪。

**已知代价**：seg10 肩后伸 >25° 从 6.0% 涨到 18.7%（>40° 0.1%→2.1%）。降权重到 3 不解决（>40° 只到 1.8%）且另两段肘反折变差，判断是结构性的——肘从连线前面摁到后面，本来就会往身后摆；改前那个漂亮数字有一部分是靠肘反折「省」出来的。25° 属正常范围，`armBack` 仍在兜底，接受。

## 四、踩到的坑

**拣货面底沿贴地时 `base` 必须填 0**。之前默认 0.3，反解出的整个场景连同相机一起竖直平移 30cm，而**反投影残差一点都不变**，画面上完全看不出来。已改默认值 + 表头提示，并用 `scripts/resolve_calib.py` 把 5 份已存标定按 base=0 重跑。
