## 三、问题与结论

### 1. 为什么不能和实验仓 `/play` 对齐

不是模型没换成同一套 RTMPose-M + 720，是时间轴和像素锁不住：

| | 实验仓 dump | 本仓直播 |
|--|-------------|----------|
| 左右路 | 同一视频帧号 | 两路 RTSP + 配对窗 |
| 叠图 | 画在产出该 pose 的那一帧 | 叠在另一路直播流上 |
| 密度 | ~25fps 每帧 2D | ~7.5Hz pose |
| 滤波 | 整段 pack（帧密） | 只能因果、看不见未来 |

现场两路差几十毫秒可以接受；**25≠15 再乘 interval=2** 才是平滑窗失效的主因。同一套 σ 在 7.5Hz 上等于猛糊五官、或把两帧姿势插成橡皮泥。

### 2. 2D 头部「又认不好」

- UI 画的是 worker **因果平滑后的配对人**，不是生检测。
- 五官点挤在几十像素里，7.5Hz 身体档 σ 最容易糊、拖。
- 单路 3D **故意不抬** `FACE_JOINTS`（防贴墙长射线），那是 3D 策略，不是 2D 关掉头。
- 直播视频和 overlay 不同步，头动得最快，错位最先被看成「头坏了」。

### 3. 3D 橡皮泥根因（已改）

为了让 3D 窗「看见上一帧」，`live_adapt_sigma` 把每关节高斯加宽到 ~2.5 个 pose 周期 → **肩到了、腕还在上一帧**。骨长中位再一收，合法伸手也被拧。  
现改为刚体平移（质心）+ 本帧形状。三角化噪声仍在，但不应再像橡皮泥。
