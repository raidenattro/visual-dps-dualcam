| `tests/test_infer_resolution.py` | 360p 帧 + 720p 探测、ffmpeg vf 单测 |

部署：重启对应 `visual-dps-infer-*`；改分辨率后仍建议重启 infer 容器。

## 十一、直播页：手腕接触无告警（已排查，未改代码）

### 现象（aisle11 等）

- 2D 上手腕明显伸进货格，3D 腕点为橙色（`WRIST_FAR`，**非**告警绿 `WRIST_NEAR`），HUD 无「告警 shelf:box」。
- 有时左路「等待姿态数据…」、右路有 2D，3D 窗仍在画骨架（见 §十二）。

### 根因链（按优先级）

**A. 告警出口只接在 `pick_pairs` 成功路径**

```
process_pair → pick_pairs 成功 → _lift_joints → wrist_tok → alarm_collisions ✓
             → pick_pairs 失败 → _lift_follow → _tok 算了但丢弃 → alarm_collisions = [] ✗
```

L/R 时差超配对窗时 worker 改 `process_single`，同样 **`alarm_collisions` 恒 []**。

**B. `_lift_follow` 双路分支的缺口（待修候选）**

同帧 L/R **都有 pose**，但配不上立体时，`_lift_joints(L+R)` **已算** `contact_slots`，结果被 `_tok` 丢弃，且 `wrist_alarm` 写死 `{9:false,10:false}`。  
这不是「单侧 hold/mono」——是 **双侧算完、告警被关**。

**C. 几何门槛（与是否配对无关）**

| 项 | 现网 | 含义 |
|----|------|------|
| `contact_m` | `0.0`（`runtime_config` / 巷道 JSON 可配） | 仅 `signed_wall_dist < 0`（伸进墙）才报；**贴墙 d=0 不报** |
| `CONTACT_SRC` | `stereo` / `L` / `R` | `Lhold`/`Rhold`/`Lmono`/`Rmono` **只显示不报警**（单侧语义） |
| 肩-腕 > 0.85m | `_clamp_flying_wrists` | 收腕并 **清空** 该腕 token |
| 货格 YZ | `contact_slots` | X 进墙但 Y/Z 不在 cell 内 → 不报 |

**单侧语义**：仅一路 2D 参与抬点（`process_single` 或 `_lift_joints(..., None, None)`）→ 3D 深度不可信，故意不报贴墙。与 `contact_m` 无关。

### 待产品拍板（问题 1）

1. **`pick_pairs` 失败但 L/R 同帧双路 `_lift_follow`**：是否把已有 `_tok` 接到 `wrist_alarm` / `alarm_collisions`（仍要求 `src ∈ CONTACT_SRC`）？  
   - 偏安全：preview 也报，减少「/contact 无 alarm」  
   - 偏保守：仅 `pick_pairs` 成功才报，误报少但「有时不响」继续存在  
2. **`contact_m`**：是否从 `0` 调到 `0.03~0.05`（贴墙/近墙也报）？标注页与 `dualcam.contact_m` 已可配。

## 十二、直播页：单侧 2D 仍画 3D（修复方案）

### 现象

- 左路无骨架（「等待姿态数据…」），右路有 2D；3D 窗仍显示整副骨架，常偏到未标墙一侧。
- HUD 可能显示「单路预览 · 等待对侧配对成立体」，但 **3D 组件未隐藏 preview 骨架**。

### 根因

| 层 | 行为 |
|----|------|
| worker | `process_single` / `pick_pairs` 失败 → `persons_3d` 非空、`preview: true`（hold/单路跟上） |
| `mergeAisleOverlay` | 注释写明 **不做 preview 筛选**；`newerOverlay` 取较新一路的 `persons_3d` |
| `AisleScene3D` | 收到即画，不判断左右是否都有 2D |

### 推荐修复（前端为主，改动小）

**文件**：`web/src/pages/AisleLivePage.jsx`

在送 3D 前加 **展示门控**（2D 仍照常叠在各自画面上）：

```javascript
const hasSkelL = (overlayL.skeletons?.length || 0) > 0;
const hasSkelR = (overlayR.skeletons?.length || 0) > 0;
const raw3d = src3d.persons3d || [];
// 仅左右都有 2D 且非 preview 才画 3D；否则 3D 窗空白，HUD 仍可有「单路预览…」
const persons3dForScene =
  hasSkelL && hasSkelR ? raw3d.filter((p) => !p.preview) : [];
```

`<AisleScene3D persons3d={persons3dForScene} … />`；HUD/`collisions`/`alarms` 逻辑可继续用 `raw3d` 或同样过滤，避免 preview 路径误亮货格（与 §十一 问题 1 策略一致时再定）。

**可选后端收紧**（非必须）：`process_single` 返回 `persons_3d: []`，只保留 `skeletons_*`；SSE 体积更小，但失去 worker 侧 hold 调试信息。建议 **先做前端门控**，现场验证后再决定是否收后端。

### 验证

1. 只挡一路 infer 或让一路长时间无检测 → 3D 窗应空，2D 正常。  
2. 左右都有骨架且立体配对成功（HUD「立体骨架」）→ 3D 正常。  
3. 配对失败但左右都有 2D → 按 §十一 拍板：若仍 `preview:true`，3D 仍隐藏（上式 `filter(!preview)`）。
